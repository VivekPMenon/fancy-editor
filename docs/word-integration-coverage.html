Word → OOXML → JSON: Feature Coverage

What the one-way OOXML import pipeline reliably transposes into our JSON / HTML today, and where the gaps are. Two effort lenses per feature: to support in the editor (fully editable) versus to render in the feed (read-only). Read-only rendering has fewer constraints, so several things that are hard to make editable are much cheaper to simply display — worth knowing when a feature only needs to be seen, not edited.

The feed lens changes the math. When a feature only needs to be seen, not edited, several "hard for the editor" items drop a tier — charts and equations Hard → Medium (render the cached raster / MathML), tracked changes and footnotes Medium → Easy (static styled markup). Only genuine vector shapes stay expensive, and live fields stay infeasible either way.  ·  Direction: one-way import (Word authors, we publish); no full round-trip back into Word.
